## 🔴 P0 — 严重（数据丢失 / 崩溃 / 不可移植）

### Bug 1：AI 回复覆写通讯录用户信息（数据丢失）

**文件**：`dmshoot/gui/main_window.py` — 第 493~497 行

**问题**：`_on_ai_response()` 调用 `database.upsert_session()` 时，`SessionRecord` 只填了 4 个字段：

```python
database.upsert_session(SessionRecord(
    session_id=session_id,
    platform=session_id.split(":")[0],
    last_message=reply_text[:50],
    last_time=now,
))
```

其余字段 `peer_name`、`peer_id`、`avatar_url` 都是空字符串默认值。

`upsert_session` 的 SQL 是：
```sql
ON CONFLICT(session_id) DO UPDATE SET
    peer_name=excluded.peer_name,
    peer_id=excluded.peer_id,
    ...
    avatar_url=excluded.avatar_url
```

→ **每次 AI 自动回复后，该会话在通讯录中的用户昵称和头像就会被空字符串覆写**。

**触发条件**：AI 自动回复任何一条消息。

**修复建议**（二选一）：
1. **简单**：在 `_on_ai_response` 中先查已有 session，只更新 `last_message`/`last_time`，用 UPDATE SQL 而非 upsert
2. **更彻底**：在 `database.py` 中新增 `update_session_last_msg(session_id, text, ts)` 函数，只更新这两个字段，不动 name/face

### Bug 2：硬编码绝对路径 — 换机器直接崩

**文件**：`dmshoot/utils/douyin_signer.py` — 第 17~19 行

```python
_NODE = r"C:\Users\Administrator\.workbuddy\binaries\node\versions\22.12.0\node.exe"
```

  ```python
  _NODE_MODULES = _ROOT / "external" / "DouYin_Spider" / "node_modules"
  ```

### Bug 3：相对路径状态文件 — 依赖 cwd

**影响文件**（共 4 处）：

| 文件 | 行号 | 路径 |
|------|------|------|
| `dmshoot/plugins/douyin/adapter.py` | 19 | `Path("dmshoot/data/douyin_state.json")` |
| `dmshoot/plugins/bilibili/adapter.py` | 17 | `Path("dmshoot/data/bilibili_state.json")` |
| `dmshoot/plugins/xiaohongshu/adapter.py` | 26 | `Path("dmshoot/data/xhs_state.json")` |
| `dmshoot/gui/widgets/contact.py` | 15 | `Path("dmshoot/data/avatars")` |

**问题**：这些 `Path()` 是相对路径，依赖启动时的 `os.getcwd()`。如果用户从其他目录启动 `main.py`（如双击快捷方式、或用绝对路径调用），状态文件会写到错误的位置。

**修复建议**：统一用 `Path(__file__)` 向上推导到项目根：
```python
_ROOTS = {
    "douyin": Path(__file__).parent.parent.parent,   # dmshoot/plugins/douyin → 上3级到项目根
    "bilibili": 同上
    "xiaohongshu": 同上

}
STATE_FILE = _ROOT / "dmshoot" / "data" / "xxx.json"
```
或者更简洁：在各文件顶部定义一个 `_PROJECT_ROOT` 常量。

## 🟠 P1 — 重要（功能异常 / 竞态条件）

### Bug 4：抖音 session_id 格式分裂 + send_message 不兼容

**文件**：`dmshoot/plugins/douyin/adapter.py`

**问题 4a**：第 246 行，有新消息时创建 session_id 的逻辑：

```python
session_id = f"douyin:0:1:{peer_uid}:{self._my_uid}:0:" if peer_uid \
             else f"douyin:{conv_id}:0:"
```

**正常格式**（有 peer_uid 时）：`douyin:0:1:123456:789012:0:`（5 段，`:` 分隔）  
**fallback 格式**（peer_uid 为空时）：`douyin:98765:0:`（3 段）

两种格式完全不同。若 `_get_peer_uid_for_conv()` 对自己的消息返回空 peer_uid，同一条会话在 DB 中会变成两条不同 session。

**问题 4b**：第 109 行 `send_message()` 设定了 session_id 必须是 4 段以上：

```python
parts = session_id.split(":")
if len(parts) < 4:
    return False
peer_uid = parts[2]
```

但 fallback 格式 `douyin:98765:0:` 只有 3 段，直接返回 False → **发不出去**。

**修复建议**：
- 统一 session_id 格式，不搞 fallback
- 如果 peer_uid 确实为空，直接跳过这条消息（不创建 session，不 emit）
- 或者在 `_poll_messages` 中确保 `peer_uid` 不可能为空（从 WS 消息中一定有 sender_uid）

### Bug 5：`BaseAdapter.stop()` 冻结主线程 UI

**文件**：`dmshoot/core/adapter.py` — 第 87~91 行

```python
def stop(self):
    self._running = False
    self._connected = False
    self.wait(3000)  # ← 同步阻塞，冻结调用线程最多 3 秒
```

`QThread.wait()` 是同步调用。当用户点击「停止」按钮时，信号链是：  
LoginPage → MainWindow._stop_adapter_from_ui → adapter.stop()  
最终跑到 `wait(3000)`，主线程卡住最多 3 秒 × 适配器数量。

**修复建议**：
```python
def stop(self):
    self._running = False
    self._connected = False
    if not self.isRunning():
        return
    self.quit()
    if not self.wait(3000):
        self.terminate()  # 超时强杀
```
并在调用侧（main_window）用 `adapter.finished.connect(adapter.deleteLater)` 异步清理。

### Bug 6：`_start_adapter` 的 cookie 参数是死代码

**文件**：`dmshoot/gui/main_window.py` — 第 402 行

```python
def _start_adapter(self, platform: str, cookie: str, sessdata: str, jct: str):
    ...
    adapter = plugin.create_adapter(self.bus, self.config)  # ← 读的是 config
```

方法签名中的 `cookie`, `sessdata`, `jct` 三个参数**从未使用**。实际适配器创建通过 `plugin.create_adapter(self.bus, self.config)`，内部用 `getattr(config, field_name)` 直接从 config 对象取值。

虽然目前不影响运行（调用方 `_start_adapter_from_ui` 传的也是 config 对象里的值），但会造成维护困惑。

**修复建议**：删除这三个无用参数，简化为 `_start_adapter(self, platform: str)`。

### Bug 7：AI 热切换导致上下文丢失（竞态）

**文件**：`dmshoot/gui/main_window.py` — 第 470~473 行 + 第 474~486 行

消息到达后，AI 回复通过 QTimer 延迟触发：
```python
QTimer.singleShot(max(delay_ms, 500), lambda: self._call_ai(msg))
```

`_call_ai` 内部：
```python
class _AIThread(QThread):
    def run(self):
        reply = asyncio.run(get_ai().handle_message(msg))  # ← 执行时才取 AI 实例
```

如果在 QTimer 延迟期间用户切换了提示词（触发 `init_ai()` 替换全局 AI 单例），新 AI 实例**没有旧会话的上下文历史**。

同时，`msg` 是通过 lambda 闭包捕获的，如果一个会话有连续多条消息，多个 QTimer 回调中 `get_ai()` 可能指向不同的 AI 实例，上下文完全乱套。

**修复建议**：
- 在 QTimer 创建时捕获当前 AI 实例：`ai = get_ai()`
- 传给 `_call_ai` 时带 ai 引用，而不是在 QThread 里再取

### Bug 8：扫码登录竞态 — cookie 互相覆写

**文件**：`dmshoot/gui/pages/login_page.py` — 第 234~260 行

`_on_cookie_ready` 的处理流程：
```python
cfg = database.load_config()     # 1. 读全部配置
cfg.douyin_cookie = cookies["cookie"]  # 2. 改一个字段
...
database.save_config(cfg)        # 3. 写回全部配置
```

如果用户先扫抖音、再快速扫 B 站，两个扫码的 cookie 回调几乎同时触发：
1. 抖音回调 → load → 改 douyin_cookie → save（此时 B 站字段是旧的）
2. B 站回调 → load → 改 bilibili_sessdata → save（**覆写了步骤 1 刚写入的抖音 cookie**）

**修复建议**：改为只更新需要的字段：
```python
from dmshoot.storage import database
database.save_single_config("douyin_cookie", cookies["cookie"])
```
或在 `database.py` 中新增 `update_config_field(key, value)` 函数。

### Bug 12：数据库迁移每次启动都跑

**文件**：`dmshoot/storage/database.py` — 第 93~96 行

```python
cur.execute("""
    UPDATE messages SET platform = SUBSTR(session_id, 1, INSTR(session_id, ':') - 1)
    WHERE platform = '' AND session_id LIKE '%:%'
""")
```

即使所有消息的 `platform` 列已回填完毕，这个 UPDATE 仍然每次启动都执行一次全表扫描。

**修复建议**：加条件避免空跑：
```sql
WHERE platform = '' AND session_id LIKE '%:%'
  AND EXISTS (SELECT 1 FROM messages WHERE platform = '' LIMIT 1)
```

### Bug 14：`send_message` 缺少防御性解析

**影响文件**（3 处）：

| 文件 | 行号 | 解析方式 |
|------|------|----------|
| `dmshoot/plugins/bilibili/adapter.py` | 222 | `int(session_id.split(":")[-1])` |
| `dmshoot/plugins/xiaohongshu/adapter.py` | 113 | `session_id.split(":")[-1]` |
| `dmshoot/plugins/douyin/adapter.py` | 109 | `session_id.split(":")[2]` |

如果 session_id 格式意外变化（如 Bug 4 的 fallback 格式），抛 `ValueError` / `IndexError` 导致回复发送失败却无清晰日志。

**修复建议**：加 try/except + 日志：
```python
try:
    talker_id = int(session_id.split(":")[-1])
except (ValueError, IndexError):
    logger.error(f"无法解析 session_id: {session_id}")
    return False
```
