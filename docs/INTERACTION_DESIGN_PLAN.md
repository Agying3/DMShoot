# DMShoot 交互设计实施计划

> 版本：2026-08-30  
> 目标：在不牺牲消息吞吐和稳定性的前提下，让 DMShoot 的操作反馈更接近正式桌面应用。

## 1. 当前基线

| 项目 | 当前结果 | 结论 |
|---|---:|---|
| 页面切换 | P50 10.4ms / P95 15.4ms | 原始响应够快，缺少视觉连续性 |
| 聊天滚动 | 约 62.5fps | 日常滚动已接近 60Hz |
| 设置页打开 | 首次约 43ms | 无需增加阻塞式加载页 |
| 性能页首次加载 | 约 275ms | 需要明确的首次加载反馈 |
| 连续消息（100条、间隔5ms） | UI 延迟 P95 7.6ms | 日常消息链路流畅 |
| 100条瞬时消息 | 主线程占用约 181ms | 动效必须在消息洪峰时自动降级 |

## 2. 设计原则

1. **先反馈，后完成**：点击后 100ms 内必须出现按下、加载或状态变化。
2. **动效不掩盖延迟**：常规动效控制在 100-160ms，不使用长距离移动。
3. **不打断用户**：成功提示优先使用非模态轻提示，只有必须确认的错误才使用弹窗。
4. **不抢阅读位置**：用户查看历史消息时，新消息不能强制滚动到底部。
5. **洪峰优先性能**：聊天气泡不使用逐条透明特效，只保留增量渲染。
6. **状态以真实连接为准**：保存 Cookie 不等于在线，绿色只表示真实监听连接成功。

## 3. 状态语义

| 状态 | 颜色与表现 | 含义 |
|---|---|---|
| 未登录/未启用 | 灰色静止 | 当前没有有效在线连接 |
| 连接中 | 黄色交替呼吸 | 正在启动、验证或等待首次握手 |
| 重连中 | 橙色循环追逐 | 连接中断，程序正在自动恢复 |
| 在线 | 绿色轻呼吸 | 监听连接已经真实建立 |
| 登录失效/错误 | 红色闪烁 | Cookie 过期、认证失败或不可恢复错误 |

状态灯悬停时显示平台名、当前状态和最近一次状态消息。

## 4. 分阶段实施

### 第一阶段：感知流畅度（本轮）

- [x] 侧边栏增加平滑移动的选中指示条。
- [x] 主页面保持即时切换，由侧边栏指示条提供视觉连续性。
- [x] 新增可复用的非模态轻提示，用于保存成功、登录成功和发送失败。
- [x] 平台状态增加“重连中”语义和状态详情提示。
- [x] 聊天窗口增加“X条新消息”悬浮按钮。
- [x] 用户查看历史时保持滚动位置，点击悬浮按钮后回到底部。
- [x] 经真实窗口 A/B 后取消整页淡入和逐气泡淡入，避免交互设计反向拖慢界面。

### 第二阶段：操作闭环

- [ ] AI 消息增加发送中、成功、失败状态。
- [ ] 发送失败提供原地重试按钮，避免重新输入。
- [ ] 扫码、清缓存和连接按钮统一加载状态与防重复点击。
- [ ] 设置字段保存后显示短暂勾选反馈，不弹出确认框。

### 第三阶段：重页面与列表

- [ ] 性能页首次加载超过 100ms 时显示紧凑加载指示。
- [ ] 性能图表使用固定采样频率和插值，避免整页频繁重绘。
- [ ] 联系人列表只更新变化项，并保持当前选择和滚动位置。
- [ ] 评估聊天气泡进一步虚拟化，解决极端消息洪峰停顿。

## 5. 动效与性能预算

| 项目 | 预算 |
|---|---:|
| 页面内容切换 | 即时，不做整页透明合成 |
| 导航指示条 | 150ms，OutCubic |
| 聊天气泡 | 不启用逐气泡特效 |
| 轻提示淡入/淡出 | 120ms / 160ms |
| 单次交互新增主线程工作 | P95 不超过 4ms |
| 日常消息滚动目标 | 60Hz 下 P95 不超过 20ms |

禁止对聊天列表整体几何尺寸、阴影模糊半径和大面积背景做持续动画。

## 6. 第一阶段验收

1. 页面连续切换保持即时，不出现黑屏或失去点击响应。
2. 登录成功回到首页时，侧边栏选中状态与页面一致。
3. 查看历史消息时连续收到消息，滚动位置不跳动且计数准确。
4. 点击新消息按钮后到达底部，计数清零并隐藏按钮。
5. 100 条连续消息到达时，新交互不创建持续的逐气泡合成任务。
6. 100 条瞬时消息时不启动气泡透明动画。
7. 绿色状态灯只在适配器发出在线状态后出现。
8. GUI 自动化、并发、性能和集成测试全部通过。
