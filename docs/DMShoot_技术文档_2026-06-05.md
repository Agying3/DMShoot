## 1. 项目概述

DMShoot 是一套桌面端的 AI 值守私信监控系统，对接 **抖音 / B站 / 小红书** 三大平台的消息体系，用 DeepSeek AI 自动回复粉丝私信，提供统一的 GUI 管理界面。

| 属性 | 值 |
|------|-----|
| 语言 | Python 3.12+ |
| GUI框架 | PySide6 (Qt6) |
| 数据库 | SQLite (WAL模式) |
| AI引擎 | DeepSeek API (兼容 OpenAI 格式) |
| 平台适配 | 抖音(WebSocket) / B站(轮询) / 小红书(REST轮询) |
| 签名方案 | Node.js subprocess + dy_ab.js |

## 3. 核心架构

### 3.1 架构总览

```
main.py
  └── MainWindow
        ├── MessageBus (单例) ←→ 全局事件中枢
        ├── PluginManager → [DouyinAdapter, BilibiliAdapter, XHSAdapter]
        ├── AIBackend (DeepSeek API)
        ├── ConcurrencyManager (共享线程池, 8线程)
        ├── GUI层 (Sidebar + HomePage + LoginPage + ...)
        ├── Storage层 (SQLite WAL)
        └── Utils层 (扫码/签名/WS/解析)
```

设计理念：**所有组件只跟 MessageBus 通信，互相不直接耦合**。GUI 发消息、AI 回复、适配器收消息，全部通过总线中转。

### 3.2 MessageBus（消息总线）

全局事件中枢，线程安全单例模式（双重检查锁）。

**核心信号**:

| 信号 | 参数 | 用途 |
|------|------|------|
| `new_message` | `Message` | 新消息到达 |
| `send_reply` | `platform, session_id, text` | 请求发回复 |
| `platform_status` | `platform, status, msg` | 平台状态变更 |
| `log` | `level, platform, message` | 日志输出 |
| `ai_request` | `Message` | AI回复请求 |
| `ai_response` | `session_id, reply, model` | AI回复结果 |

**状态常量**: `PlatformStatus.OFFLINE` / `CONNECTING` / `ONLINE` / `ERROR`

### 3.3 BaseAdapter（适配器基类）

所有平台适配器继承 `QThread`，独立线程运行。子类必须实现：

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `connect()` | `bool` | 建立连接 |
| `disconnect()` | — | 断开清理 |
| `send_message(session_id, text)` | `bool` | 发消息 |
| `fetch_sessions()` | `list[dict]` | 获取会话列表 |
| `fetch_history(session_id, limit=20)` | `list[Message]` | 获取历史 |
| `_poll_messages()` | — | 轮询新消息 |

生命周期: `run()` → `connect()` → `_poll_loop()`(循环) → `disconnect()`

### 3.4 ConcurrencyManager（并发管理器）

全局共享线程池，8个工作线程，三级优先级：

| 优先级 | 常量 | 用途 |
|--------|------|------|
| HIGH | `PRIO_HIGH=0` | AI回复、消息发送 |
| MEDIUM | `PRIO_MEDIUM=1` | 批量同步、会话拉取 |
| LOW | `PRIO_LOW=2` | 头像下载、缓存刷新 |

**背压控制**: 总队列200条上限，单平台60条上限。HIGH优先级永不拒绝。

### 3.5 Message（统一消息模型）

`@dataclass` 跨平台统一消息模型：

| 字段 | 类型 | 说明 |
|------|------|------|
| `platform` | str | douyin/bilibili/xiaohongshu |
| `msg_type` | str | text/image/voice/video/system |
| `sender_id` | str | 发送者唯一ID |
| `sender_name` | str | 昵称 |
| `session_id` | str | 会话ID |
| `content` | str | 文本内容 |
| `timestamp` | float | Unix时间戳 |
| `is_self` | bool | 是否自己发出 |
| `is_auto_reply` | bool | 是否AI回复 |

## 4. 平台适配器

### 4.1 抖音 (DouyinAdapter)

| 属性 | 说明 |
|------|------|
| 通信方式 | WebSocket实时 + protobuf缓存历史 |
| 签名方案 | Python → subprocess Node.js → dy_ab.js → a_bogus/req_sign |
| Session ID | `douyin:0:1:{peer_uid}:{my_uid}:0:` |
| 认证流程 | Cookie → create_auth() → perepare_auth()(web_protect) → ticket |
| 历史同步 | 三级缓存 (L1 JSON → L2 Protobuf → L3 Playwright) |
| 去重机制 | 内存set + DB `INSERT OR IGNORE` 双重防护 |

**关键技术**:
- 消息ID高32位为Unix秒(抖音Snowflake)，用于时间戳解码
- ticket提取路径: `_bd_ticket_crypt_cookie` cookie (非localStorage)
- WebSocket 15秒ping心跳防踢

### 4.2 B站 (BilibiliAdapter)

| 属性 | 说明 |
|------|------|
| 通信方式 | bilibili-api-python SDK，3秒轮询 |
| Cookie | SESSDATA + bili_jct |
| 历史同步 | ConcurrencyManager并行拉取所有会话 |
| 时间戳处理 | 多字段兼容(timestamp/msg_time/mtime/ctime)，毫秒自动转秒 |
| 去重机制 | JSON状态文件 `bilibili_state.json` + 内存set |

### 4.3 小红书 (XHSAdapter)

| 属性 | 说明 |
|------|------|
| 通信方式 | 纯REST API，3秒轮询 |
| API域名 | `edith.xiaohongshu.com` |
| 端点 | 登录验证、消息列表、发送消息、用户信息 |
| 历史同步 | 分页拉取(最多10页) + 批量预取用户信息(避免N+1) |
| 去重 | 基于 msg_id 去重 |

## 6. AI 模块

### 6.1 AIBackend

- 兼容 OpenAI API 格式，支持流式/非流式
- 默认模型: `deepseek-v4-flash`
- 上下文窗口: 最近10轮
- 每会话独立上下文，切换对话自动重建
- 支持热更行为提示词（不丢上下文）
- 历史消息超过5分钟不触发AI（避免积压唤醒）

**API调用**: `POST /v1/chat/completions`，日志记录耗时+token+思考过程

### 6.2 提示词系统

- **角色提示词**: `prompts/` 目录下 .txt 文件，控制AI人格
- **行为提示词**: `prompts/行为/` 子目录，控制回复风格
- 支持UI内选择、新建、删除

## 7. 存储层

### 7.1 数据库

SQLite `dmshoot/data/dmshoot.db`，WAL模式，持久连接。

**表结构**:

| 表 | 用途 | 唯一索引 |
|----|------|----------|
| `sessions` | 会话记录 | `session_id` |
| `messages` | 消息记录 | `(session_id, content, is_self)` |
| `config` | 键值对配置 | `key` |

**核心操作**:
- `upsert_session()` — 插入/更新会话（avatar_url空值不覆写）
- `save_message()` — INSERT OR IGNORE 去重
- `save_messages_batch()` — executemany 批量写入
- `get_messages(session_id, limit=100)` — 获取消息（oldest first）

### 7.2 数据模型

**AppConfig** — 应用配置（dataclass，~25字段）:
- AI: `api_key`, `base_url`, `model`, `system_prompt`, `prompt_preset`
- 抖音: `douyin_cookie`, `douyin_enabled`
- B站: `bilibili_sessdata`, `bilibili_jct`, `bilibili_enabled`, `bilibili_auto_monitor`
- 小红书: `xhs_cookie`, `xhs_enabled`
- 回复: `auto_reply_enabled`, `reply_delay_min/max`, `max_context_rounds`
- 界面: `wallpaper_path`, `wallpaper_gallery`

## 9. 数据流

```
用户私信到达
    │
    ▼
Adapter._poll_messages()  ← 轮询/WebSocket
    │
    ▼
Adapter._on_message(msg)
    │
    ▼
MessageBus.emit_message(msg)
    │
    ├──► GUI: HomePage.add_message() → ChatView气泡
    │
    ├──► Storage: database.save_message()
    │
    ├──► AI: AIBackend.handle_message()
    │          │
    │          ▼
    │      DeepSeek API → 生成回复
    │          │
    │          ▼
    │      MessageBus.ai_response
    │          │
    │          ├──► GUI: MonitorPanel记录
    │          │
    │          └──► MessageBus.send_reply
    │                    │
    │                    ▼
    │              Adapter.send_message() → 平台API发送
    │
    └──► Log: Console/终端日志输出
```

## 11. 开发注意事项

1. **不能私自修改代码** — AI 只提供分析和建议，所有代码改动由用户手动执行
2. **签名依赖 Node.js** — 非GUI环境PATH差异已通过 `_find_node()` 惰性解决
3. **抖音ticket提取** — ticket在 `_bd_ticket_crypt_cookie` cookie中，不在localStorage
4. **消息去重** — 依赖DB唯一索引 `(session_id, content, is_self)` + 内存set
5. **protobuf版本** — 强制使用 4.25.9，不兼容 7.x 的 runtime_version
6. **数据库锁** — 所有写操作包裹 `with _lock:` 防并发竞态
7. **UI风格** — 透明毛玻璃+细边框+大圆角+青色强调色，无emoji按钮
8. **QSS优先** — 气泡颜色走QSS而非QPalette，确保border-radius正常渲染
