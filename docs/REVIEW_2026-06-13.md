## 🔴 实际影响运行的 Bug

### BUG #1 — AI 自动回复开关完全失效

**位置**: `main_window.py:852-867`  
**严重度**: 高

```python
# _on_new_message() 中触发 AI 的条件:
ai = get_ai()
if ai.configured and msg.msg_type == "text":  # ← 只检查 AI 是否配置，没查 auto_reply_enabled
    ...
    timer.timeout.connect(lambda a=ai, m=msg: self._call_ai(m, a))
```

**现象**: 在设置中关闭"启用自动AI回复"，AI 仍然回复。

**根因**: `auto_reply_enabled` 在设置 UI 中有关联的 checkbox（`settings_dialog.py:319`），也存入了 DB（`models.py:78`），但**唯一的消费点缺失**——`_on_new_message()` 从未检查它。

**修复**:
```python
if (ai.configured and self.config.auto_reply_enabled
    and msg.msg_type == "text"):
```

### BUG #2 — AI 上下文重复注入

**位置**: `ai/backend.py:68-69, 83-91`

这是上次审查遗留的 bug，至今未修：

1. `_on_new_message` → `save_message(msg)` → 消息已写入 DB
2. QTimer 触发 → `_call_ai` → `handle_message` → `chat(msg.content)`
3. `chat()` 内部:
   - `_get_or_create_context()` → 从 DB 加载最近 20 条 → **包含当前消息**
   - `ctx.append({"role": "user", "content": user_message})` → **又加一次**

每条新消息在 AI 上下文中出现两次，token 浪费 100%。

**修复**:
```python
# backend.py chat() 中
ctx = self._get_or_create_context(session_id)
# 去重：DB 刚存的最后一条就是当前消息
if not ctx or ctx[-1].get("content") != user_message:
    ctx.append({"role": "user", "content": user_message})
```

### BUG #3 — 快手登录硬编码 venv 路径

**位置**: `login_page.py:263`

```python
venv_python = r"H:\DMShoot\.venv\Scripts\python.exe"
```

**现象**: 如果在其他机器运行、venv 在其他路径、或者 Python 环境不同，快手扫码直接报错。

**修复**: 用 `sys.executable` 或动态查找:
```python
venv_python = sys.executable
```
（快手扫码子进程不需要特定 venv，用当前 Python 解释器即可）

### BUG #5 — `_on_ai_response` 绕过数据库写锁

**位置**: `main_window.py:893-898`

```python
conn = database._get_conn()
conn.execute("""UPDATE sessions SET last_message=?, last_time=? WHERE session_id=?""",
              (reply_text[:50], __import__("time").time(), session_id))
conn.commit()
```

### BUG #7 — `_stop_adapter_from_ui` 在非 Qt 线程操作 QThread

**位置**: `main_window.py:758`

```python
threading.Thread(target=adapter.stop, daemon=True).start()
```

`adapter.stop()` 内部调 `self.quit()` + `self.wait(3000)` + `self.terminate()`。在原始 Python 线程中调用 QThread 方法不安全。如果 UI 关闭时这个 daemon 线程还在跑，`terminate()` 可能操作已被销毁的对象。
