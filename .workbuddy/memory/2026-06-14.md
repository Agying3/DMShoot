## perf_chart.py 重构 — QtCharts → QPainter 纯手绘

**问题**: 点击设置齿轮或「性能」标签时，QtCharts C++ 层 segfault (access violation)，无 traceback 直接退出

**根因诊断**:
- 非 Python 异常，是 Qt C++ 层 GPU 驱动渲染崩溃
- `AA_UseSoftwareOpenGL` 无效
- `QSS 0.5px/1.5px` 小数边框改为整数也无济于事
- 任何 QChart/QChartView/QPieSeries 创建都会触发

**解决方案**: 完全移除 QtCharts 依赖，改用 QPainter 纯手绘:
- `_LineAreaWidget` — 折线/面积图 (paintEvent 绘制网格、折线、面积填充、标签)
- `_DoughWidget` — 环形饼图 (drawPie + 中心孔 + 百分比标签)
- `_BarWidget` — 柱状图 (drawRoundedRect + 数值标签)
- 保留: _GanttWidget (本就是 QPainter)、配色切换、深/浅主题、checkbox 勾选

**其他修复**:
- PerfChart.__init__ 签名: `(parent=None, m=None)` → `(m=None, parent=None)` 与 PerfWindow 调用对齐
- PerfWindow.open 签名: `(p=None, m=None)` → `(parent=None, m=None)`
- 设置页性能标签改为延迟加载 (`_perf_placeholder` + `_on_tab_changed`)
- settings_dialog.py: `PerfChart(parent=self)` → `PerfChart(parent=w)`
- main.py: 添加 `Qt.AA_UseSoftwareOpenGL` (防御，实际 QPainter 方案不需要)

## SQLite WAL 五层防御方案 — 解决 SQLiteStudio 无法打开 .db

**问题**: SQLite WAL 模式 + Python/Go 双进程各自打开独立连接。DMShoot 崩溃后 .db-wal 积压 4MB 未合并，SQLiteStudio 无法读取。

**方案**: 创建 `docs/WAL_CHECKPOINT_SOLUTION.md` + `tools/wal_checkpoint.py`，五层防御:
- L1: Python + Go 两端 `wal_autocheckpoint=200` (800KB) + `synchronous=NORMAL`
- L2: Python `atexit` + signal 退出时 TRUNCATE checkpoint
- L3: Go 每 60 秒 PASSIVE checkpoint goroutine (batch.go:122-129)
- L4: Go shutdown 前 TRUNCATE checkpoint (batch.go:135-138)
- L5: `tools/wal_checkpoint.py` 独立紧急恢复脚本 (支持 --watch 监控模式)

**用户已手动应用全部改动并重新编译 Go 二进制，验证全部通过。**
